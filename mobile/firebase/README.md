# Firebase push-notification release input

The apps request notification permission, obtain a Firebase/APNs registration token, and send it to `PUT /api/v1/mobile/devices`. The server stores only a keyed hash plus AES-GCM ciphertext protected by `HIG_ENCRYPTION_KEY`.

Before staging push acceptance:

1. Create separate Firebase applications for Student/Parent, Staff/Admin, and Driver.
2. Use distinct Android package IDs and iOS bundle IDs documented in `mobile/RELEASE_CHECKLIST.md`.
3. Add `google-services.json` and `GoogleService-Info.plist` locally or through a protected CI secret step. Never commit them.
4. Configure the server-side push provider credentials in the protected staging secret store.
5. Send a test notification to each persona and confirm delivery, tenant assignment, deep-link routing, and notification read-state behavior.

Remote provider credentials are not generated by source code and require the organization Firebase/Apple accounts.
